# PAPER AI 0.4 本地 AI 测试与验收要求

> 更新：2026-09-27。本文是当前版本的本地测试主指南与验收口径。0.2 的 33 项、单页记录和 2–4 题结果只作为历史基线，不能代替 0.4 验收。
>
> 人工使用步骤见 [0.4 人工操作指南](manual_operation_guide.md)，实现状态见 [0.4 进度](product_04_status.md)。

## 1. 验收分层

必须把以下四类证据分开，不得互相替代：

| 层级 | 证明什么 | 不能证明什么 |
|---|---|---|
| A. 自动化 / 结构测试 | 数据合同、分流校验、状态、备份等程序逻辑没有已知回归 | 浏览器真实排版、打印、实拍可用 |
| B. 浏览器 / PDF 测试 | 前端流程、双语、分页、PDF、交互能跑通 | 真实纸张和手机照片稳定 |
| C. 实物闭环测试 | 真实打印→纸上填写→手机拍照→多页扫描→校对→总结→下一轮能跑通 | 学习效果、长期保持 |
| D. 教育效果研究 | 对真实学习收益、接入频率等研究问题提供证据 | 不能由合成测试替代 |

项目目前已有 42 项 0.4 自动检查通过记录，但 B/C 仍必须按当前版本重新验证；0.2 的浏览器 / PDF 通过记录不可直接继承。

## 2. A 层：自动化与结构验收

在仓库根目录运行：

```bash
python -m unittest discover -s demo/tests -p 'test_*.py' -v
```

若有 Node / Playwright 环境，再运行当前浏览器脚本。CI 不应调用付费 AI。

A 层必须覆盖并通过：

- 自定义主题与旧方程单元隔离；
- 每组 5–10 题限制；
- 多题组结构；
- 分流按第一条匹配规则执行；
- 正确数规则覆盖 0–满分；
- 指定错题 / 知识点规则能优先触发；
- 分流目标只能指向存在的后续组或 `END`；
- 拒绝循环、悬空目标和非法组号；
- 未被路线分配的题保持“未分配”，不计错；
- 缺失 / 无法识别的数据保持“未知”；
- 重试不覆盖首次答案，不改变已经确定的分流；
- 多页记录逐页合并时不丢失其他页；
- 重复保存 / 重复提交不重复累计；
- 学情总结只读取已确认记录；
- 新记录保存后旧总结失效；
- 自定义主题不泄漏旧方程诊断 / 状态；
- 备份恢复、发行冻结和旧版本保护仍有效。

**通过条件：**全部预期自动测试通过；任何失败都要先修复或明确登记，不能用浏览器“看起来正常”覆盖失败。

## 3. B 层：浏览器与 PDF 验收

0.4 至少完成以下矩阵：

### B1. 自定义主题基本闭环

使用真实 AI 或受控 mock 生成一个自定义主题：

- 3 组 × 5 题；
- AI 讲解存在；
- 三个题组均有名称、知识点和难度；
- 第一组至少有两个不同实际去向；
- 草稿可编辑；
- 校验 → 审核 → 冻结 → 打印入口完整。

### B2. 默认题量

至少一次生成默认 **3 组 × 10 题 = 30 题** 的学习包，检查：

- 所有组均有 10 题；
- 学习册、核对册、记录纸均能生成；
- 长题面不会造成关键内容裁切；
- 稳定组号 / Q 号在分页后不改变；
- 分流目标不依赖页码。

### B3. 双语与不同主题

真实 AI 稳定性验收至少应包含：

- 中文自定义主题至少一次；
- 英文材料至少一次；
- 至少两个彼此明显不同的主题；
- 至少一次默认 30 题。

如果某次模型输出被结构校验拒绝，应保留失败记录；修复后重试可以通过，但不能把失败隐藏掉。

### B4. 整批核对与纸上分流 UI

确认界面与打印内容不会暗示“每题后立即在线判题”。纸面说明必须清楚表达：

- 先完成整组；
- 再核对首次答案；
- 再按正确数 / 特定错题执行第一条匹配规则；
- 再跳到指定组。

### B5. 多页记录

生成会产生至少两页记录的学习包或测试夹具，验证：

- 每页有独立识别信息；
- 上传第 2 页后，第 1 页数据仍存在；
- 空白页 / 未走到的题不会被自动判错；
- 同一题不会因多页重复出现而重复累计。

**B 层通过条件：**上述矩阵在当前 0.4 代码上完成，输出 PDF 无关键裁切 / 缺页 / 错号，浏览器流程无阻断性错误。截图和 PDF 应保存为证据。

## 4. C 层：真实打印、填写与手机扫描

这是当前最重要的未完成验收之一。

### C1. 准备

打印同一个学习包的：

- 学习册；
- 独立提示 / 核对册；
- 全部记录纸；
- 教师答案 / 审核版。

A4、100% / 实际大小、关闭页眉页脚。所有可能路线的纸张一次发齐。

### C2. 两条真实纸上路线

至少完成两份独立纸质记录：

1. **基础 / 补强路线**：故意构造会触发目标错题或较低正确数的首次答案；
2. **进阶 / 结束路线**：构造较好表现并进入另一组或 END。

要求：

- 学生 / 测试者确实先完成整组再核对；
- 首次答案、提示、重试分栏；
- 未访问组保持空白；
- 不需要中途联网或 AI 判断；
- 记录是否需要额外口头说明，作为纸面可用性问题。

### C3. 实拍扫描

每页使用手机拍摄原图。至少包含：

- 正常正面光照；
- 一组轻微倾斜或阴影条件；
- 多页逐页上传。

对每张图保存：

- 纸面人工真值；
- 原始识别；
- 定位结果；
- 人工修订；
- 最终保存结果；
- 校对耗时；
- 是否需要重拍 / 手动定位。

不能用校对后的结果冒充原始扫描准确率。

### C4. 路线恢复语义

扫描 / 校对后必须满足：

- 实际路线可以被恢复；
- 合理跳过题 = 未分配；
- 应答但缺失 / 读不清 = 未知；
- 重试不会覆盖首次答案；
- 第二页不会清除第一页；
- 错包 / 错页不能静默归入另一学习包。

### C5. 学情总结与下一轮

保存确认记录后生成学情总结，并再次生成同主题下一轮。

必须检查：

- 总结引用正确的题组 / Q 证据；
- 不引用未分配题作为错误；
- 能区分首次正确与提示 / 重试；
- 两条不同路线得到可解释的不同后续安排；
- 新一轮可能进入基础、中档、进阶或特定知识点，不要求机械升难度。

**C 层通过条件：**至少两条路线都完成“打印→离线纸上执行→多页实拍→校对→确认→学情总结→下一轮”，无未解决的静默错归属、数据丢页或错误计分。

## 5. 真实 AI 专项验收

当前已记录 DeepSeek `deepseek-flash` 按新版合同一次生成 15 题并通过首次结构校验，以及一次学情总结成功；这只是已有工程证据，不代表默认 30 题、多主题、双语全部稳定。

最终本地 AI 验收还需要检查：

- 自定义主题必须实际调用 Live AI；
- 未配置密钥时明确引导配置；
- API 失败明确报错，不自动变成规则结果；
- AI 返回完整讲解、题组、题目、答案和分流规则；
- 无效 JSON / 非法结构被拒绝；
- 教师修改后可重新校验；
- 至少两个不同主题；
- 中文 / 英文均有真实调用证据；
- 至少一次默认 30 题；
- 学情总结引用已确认记录；
- 第二轮请求包含上一轮有效证据。

报告应保留模型名、提示词版本、耗时、是否修复重试、最终结构校验结果；不得保存密钥。

## 6. 验收结论怎么写

每项只允许使用以下状态：

- **PASS**：已在当前版本实际执行，证据完整；
- **FAIL**：实际执行但不符合预期；
- **BLOCKED**：环境 / 设备等原因无法执行；
- **NOT RUN**：尚未执行。

不要把“旧版通过”“理论上应该”“自动测试覆盖了类似逻辑”写成当前版 PASS。

最终工程验收至少分别给出：

- A 自动化 / 结构；
- B 浏览器 / PDF；
- C 实物闭环；
- Live AI 稳定性；
- 中英文；
- 多页扫描；
- 学情总结与下一轮。

## 8. 明确延期，不计入本轮失败

以下项目目前列为后续，不应阻塞 0.4 核心闭环验收：

1. 各大主流平台的原生 API 适配；
2. 正式展示用的两个较难文 / 理知识点最终选择；
3. 扩展大量内置正式题库；
4. 长期学习效果与不同 AI 接入间隔的完整研究。

延期不等于已实现；文档和演示必须明确区分。
