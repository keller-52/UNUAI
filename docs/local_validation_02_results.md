# PAPER AI 0.2 本地验收

日期：2026-09-27，Asia/Shanghai。基线为 `b3f2b84d9592fb3abeaff0635909492bae0727b8`；结果针对本报告所在的修复提交。系统为 Windows 11 10.0.26200、Python 3.14.7、Node.js 25.1.0、Playwright 1.63.0、Chromium 153.0.8010.12。全部学习档案与答题记录为测试数据；真实 AI 调用使用用户授权的项目密钥。

## 发现并修复

1. **恢复前快照连接未关闭。** 原始 28 项 Python 测试在 Windows 上有两项因 `before-restore-*.sqlite3` 被占用而清理失败。快照连接改为显式关闭，并增加连接关闭、校验和拒绝及冲突恢复无部分写入的回归检查。
2. **教师答案页跳转页码错误。** 教师版原先根据自身页码重写路径，导致学生册第 2/3/4 页被错误标为第 1 页。现在先独立计算学生册实际分页，再回填教师版路径；覆盖两种语言、三种题量和产生续页的情况。教师版自身页脚仍按教师版分页编号。
3. **中文教师版两处漏译。** 补充答案与路径指南标题、暂无诊断证据文字。
4. **DeepSeek 空 JSON。** 最初真实第一轮收到空内容，修复请求后成功；第二轮两次空内容后明确失败，未发行第二轮学习包。官方 DeepSeek 请求现显式关闭思考模式，让固定的 2048 输出预算用于简短的题库选题 JSON；其他提供商不发送该专属参数。记录尝试的结束原因和用量，空内容提示更明确，仍最多尝试两次。

DeepSeek 官方文档说明默认启用思考模式，JSON 模式也可能返回空内容。现有记录不足以把首次空响应全部归因于 token 截断；关闭思考模式后的本轮复测成功，不代表保证所有未来响应有效。参考：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。

第二轮请求含确认后的评价，响应引用第一轮 Q1/Q2/Q3 的三个有效证据。六份真实 AI PDF 成功生成：第一轮 3/1/1 页，第二轮 4/1/1 页。用专门的无效测试字符串另行验证真实 HTTP 401，应用明确报错，无规则回退。

调用说明：在配置密钥后的首次批量脚本运行中，脚本继承了应用默认 Live AI 模式，额外产生两个真实测试包。已修正脚本，批量生成也显式选择规则模式。之后的常规验收不再因服务器配置密钥而自动付费。真实调用脚本必须传 `--run`，不加入 CI。密钥仅用于服务进程环境，未写入配置文件、报告或 Git。

## 复现与证据

```text
python demo/server.py --port 8765 --data demo/data/acceptance-02.sqlite3
python demo/server.py --port 8766 --data demo/data/acceptance-02-restore.sqlite3
python -m unittest discover -s demo/tests -p 'test_*.py' -v
node demo/tests/scanner_test.cjs
node demo/tests/browser_smoke.cjs
node demo/tests/product_browser.cjs
node demo/tests/pagination_browser.cjs
```

`PAPER_TEST_OUTPUT` 指定输出目录。恢复脚本要求 `PAPER_BACKUP_FILE` 指向 product_browser 生成的 `synthetic-backup.json`，然后运行 `node demo/tests/restore_browser.cjs`。真实调用需独立配置服务端密钥并显式运行 `node demo/tests/live_browser.cjs --run`，会产生服务费用，每轮最多一次修复请求。
