# PAPER AI 人工实物检测指南

更新：2026-09-27。适用代码：已通过本地软件验收的 `23bd7bd`（或其后的修复版本）。本指南尚未填写实测结果。目的：确认“纸张能用、照片能读、校对可信、下一轮能接上”，不测学习效果。

## 1. 下载什么、准备什么

| 项目 | 获取方式 | 是否必须 |
|---|---|---|
| 程序全部文件 | [下载已验收版本 ZIP](https://github.com/keller-52/UNUAI/archive/23bd7bdadae911566aa990a6054f47c5d1064e5c.zip)，或仓库首页 Code → Download ZIP 获取最新版本 | 必须；全部解压，不要只下载 HTML |
| Python | 已有 3.10+ 可跳过；否则从 [Windows 官方下载页](https://www.python.org/downloads/windows/)选择稳定版安装器，普通 Intel/AMD 电脑用 Windows installer (64-bit)，不要选 embeddable package | 必须 |
| 学生学习册 PDF | 启动程序，生成并审核一个学习包后，通过 Student booklet / PDF 保存 | 在程序中生成，不是仓库现成文件 |
| 独立记录纸 PDF | 在同一个学习包内，通过 Record sheet / PDF 保存 | 必须与学习册的 package ID、版本相同 |
| 教师答案 PDF | 同一个学习包内，通过 Teacher answer guide 保存 | 建议；仅检测者使用 |
| 测试记录模板 | [人工检测记录模板](manual_physical_test_record.md)，复制一份逐项填写 | 建议 |

准备电脑、Chrome/Edge、A4 打印机及白纸、深色笔、手机。首轮约需中文三题学习册 3 页＋记录纸 1 页；教师答案可只在屏幕看。再打印一份英文四题材料通常是 4＋1 页，实际以打印预览为准。额外留两张记录纸做多选/浅色笔迹测试。

运行应用无需 Node.js、npm、pip 或测试脚本依赖。验收报告里 `D:/chatgpt codex/.../test-results/` 是另一台电脑上的证据目录，不是可下载链接。不要拿其中未知编号的照片测试你新生成的学习包。

## 2. 启动程序（Windows）

1. 将 ZIP **全部解压**到一个新目录，例如 `D:\PAPER-AI-physical-test`。打开包含 `README.md` 和 `demo` 的那一层目录。用新解压目录可隔离原来的教学数据；不要覆盖或删除原有 `demo/data`。
2. 双击 `demo/start-demo.bat`。保留出现的终端窗口。浏览器应打开 `http://127.0.0.1:8765`；未自动打开时手动输入该地址。不要双击 `index.html`。
3. 若启动失败，在仓库根目录打开终端，执行 `py -3 --version`，确认 Python 版本；再执行下列命令观察错误。如只有 `python` 命令可用，将 `py -3` 换成 `python`。

```powershell
py -3 demo/launch.py
```

若已有另一个实例占用端口，保持原实例不动，改用：

```powershell
py -3 demo/launch.py --port 8766
```

随后访问 `http://127.0.0.1:8766`。确认当前页面与刚启动的目录对应，避免误操作旧数据。macOS/Linux 在解压目录运行 `sh demo/start-demo.sh`；本轮软件验收主要在 Windows，其他系统启动交互仍需记录结果。

4. 右上角选“中文”方便操作。**界面语言与材料语言独立**，后面还要在教学设置选择材料语言。部分按钮仍可能显示英文，下文保留英文名称供对照。
5. 首次实物检测选择 **Rules demo — no AI call（规则演示）**，不需要密钥。即使已有密钥，也请主动选择规则模式，先把打印扫描问题与网络/AI 问题分开定位。

## 3. 生成并保存属于同一轮的三份材料

1. 点击 **Load sample learners（加载示例学生）**，选择 Alex。这里使用明确标为 synthetic 的测试档案，不把按脚本填出的答案算作真人学习成绩。
2. 点击 **Create a learning round（创建学习轮次）**。设置：材料语言中文、题目数 3、页数预算 6、接入间隔 3 天、规则演示模式；生成方案。
3. 展开题目、答案和辅导内容，确认都可理解。检查节点 Q1、R1、Q2、R2、Q3、END 及其跳转。勾选审核，再点 **Approve & freeze this version**。
4. 抄下学生编号、学习包编号 `PKG-...`、版本和记录纸顶部的 Sheet 编号。以下文件都从这一个学习包打开，不要在中间另生成一轮。
5. 分别打开学生册、记录纸、教师版。点击 **Print / Save as PDF**，选择“另存为 PDF”。建议命名 `PKG-编号-booklet-zh.pdf`、`PKG-编号-record-zh.pdf`、`PKG-编号-teacher-zh.pdf`。这是本次需要保留/下载的三个 PDF。
6. 确认 PDF 无缺字、截断、空白多页；教师版的跳转页码指向学生册，不是教师版自己的页码。长文本可能增加页数，不能一概认定必须三页。

实际打印：A4、纵向、**100%/实际大小**、关闭浏览器页眉页脚、单面、每张一页；不要用“适合页面”“多页合一”“小册子”。先开“背景图形”保留版面。首张只打印记录纸，检查四个黑方块和顶部编码是否完整；如果打印机裁切定位点，先解决打印设置/设备问题，再继续，不把裁切版当正常样本。

记录纸仅一页，学习册与记录纸分开。教师答案不要发给进行真实独立学习的人；本次技术检测可由检测者查看答案来构造指定路径。

## 4. 在真实纸上填写：先做一条有补救的路径

这一步是**人为构造的工程测试**。先在记录模板写下预期答案，作为对照真值，然后填涂纸张。每个字段只填一个圆圈，用深色笔填满，不只打钩。

按三题学习包，构造 Q1 首次答错、进入 R1，Q2/Q3 首次答对的路径；以打印出的跳转为准。常规编译结果对应下表：

| 记录行 | 访问顺序 | 首次答案 | 提示等级 | 重试答案 |
|---|---:|---|---:|---|
| Q1 | 1 | 选一个会跳到 R1 的错误选项 | 1（实际查看第一级提示） | 可在补救后填写正确选项 |
| R1 | 2 | 留空 | 留空 | 留空 |
| Q2 | 3 | 教师版标注的正确选项 | 0 | 留空 |
| R2 | 全行留空 | 留空 | 留空 | 留空 |
| Q3 | 4 | 教师版标注的正确选项 | 0 | 留空 |
| END | 5 | 留空 | 留空 | 留空 |

先填首次答案，再查看提示/补救。**不要擦掉首次错误答案；重试答对也仍按首次答案的路线走。** 访问顺序不是题目编号，R 与 END 同样要记访问顺序。提示 0 是“明确未用”，空白是“未知”，二者不同。看了 R1 讲解不等同于看了第一级提示，因此本脚本要求另外实际查看一级提示。

走完后记录：是否看懂跳转、是否需要检测者口头提醒、找提示/记录行是否费力、完成操作用时。技术填答时间不要写成学习效率数据。

## 5. 拍照、上传、识别与校对

1. 纸张放平，正向朝上，四角方块和顶部编码均在画面内；光线均匀，避免手和手机投影。第一张尽量从正上方拍清晰照片，保留纸外少量边缘。先做正常条件，再做困难条件。
2. 将**原图**传到运行程序的电脑，保留 JPEG/PNG/WebP 格式。iPhone 若得到 HEIC，另存/转换为 JPEG；不要把 PDF 直接传给扫描器。尽量不用聊天软件压缩后的预览图。
3. 进入 **Collect evidence（回收学习记录）**，选中纸上同一个 `PKG-...`。上传刚拍的照片。手机不能直接打开电脑的 `127.0.0.1`；现版流程是先把照片传到电脑。
4. 检查红色四角定位点是否在黑方块中心。自动定位不对时，点 Reset corners，按 **左上→右上→右下→左下**点击黑方块中心，再点 Read marked circles。照片应正向；不要依赖自动旋转。
5. **先保留原始识别结果，再修改。** 对照纸张与第 4 节预期表，记录：正确字段、误读字段、被标为未知的字段、自动/手动定位、报错。截图保存识别结果。不要先人工修到全对再声称扫描准确率 100%。
6. 在校对表修正误读/空白项。看不清就回看原图、重拍或保留未知，不能凭预期替学生猜答案。勾选“已核对”，点击 Confirm & analyse evidence。
7. 对这条完整脚本，预期：路径 Q1→R1→Q2→Q3→END；首次正确 2/3，无提示正确 2/2；R2 未访问；重试答对不覆盖 Q1 首次错误。若实填内容不同，以实际记录为准。
8. 再按相同内容保存，应不重复计分。导出本轮 JSON，并下载完整备份。原照片与 PDF 自己保留，程序不会替你保存原始照片。

重复拍同一张纸时，可反复“上传→识别→截图”，在全部拍摄条件结束后只确认最终记录，避免把同一份纸的多次照片当作多次独立学习。

## 6. 最小测试组合及成功标准

| 编号 | 做法 | 重点与预期 |
|---|---|---|
| P01 正常中文 | 上述中文三题，正常光线、正面照片 | 完整读出编号；逐字段对照，校对后评价符合纸张 |
| P02 正常英文 | 新建英文四题包，填全对路径 Q1→Q2→Q3→Q4→END；每题提示 0，R1/R2/R3 留空 | 实印四题的八行记录纸无裁切；跳转页码一致；校对后首次/无提示均 4/4 |
| P03 轻微倾斜 | 对 P01 同一张纸换一个轻微斜角拍摄 | 记录自动定位与手动定位后的差异；不预设一定识别成功 |
| P04 阴影 | 同一张纸局部有轻度阴影，再拍一张 | 记录误读和未知数、校对耗时；失败也保留样本 |
| P05 浅色/多选 | 用额外记录纸，在某个实际作答字段浅填，另一个字段填两个圈，写明具体位置 | 重点观察是否提示不确定；若静默读成确定值，记为缺陷，不按正常样本通过 |
| P06 错包/裁切 | 用 P01 照片故意选择 P02 包；另存一张裁去定位点的图片 | 错包应拒绝。裁切图片应提示或需重拍；不得猜造标记后宣称通过 |

建议初轮至少 P01、P02 各拍 3 张正常照片，再做 P03–P06。六张照片可能只来自两份纸，必须分别报告“物理纸张数”和“照片数”，不能当作六名学生或六份独立答卷。

建议内部通过条件（不是现有实测结果）：正常样本所有校对后的数据与纸张一致；无未解决的静默误读；页码、节点、编号无错误；错包无法提交成错误归属；所有异常有可执行的补救办法。原始识别率和校对时间如实填数，当前不设未经验证的 95%/99% 承诺。

统计口径：对每张正常照片，比较记录表中实际存在的“访问顺序、首次答案、提示、重试”字段，不计 R/END 上不存在的答案格。每个预期单值/空白字段均计一项；原始值与预期相同才算正确。预期单值被识别成未知计入不一致并单列；有意多选不放入普通单值准确率分母，单独报告是否安全提示。整张无法定位的照片单列失败，不能从总照片数里隐去。校对计时从原始结果出现到确认完成，另记重拍与人工定位时间。

## 7. 接上真实 AI 与下一轮（物理流程顺利后）

规则模式也能完成下一轮更新，但它不是 AI 成果。若要检查最终展示链路，在仓库根目录执行：

```powershell
py -3 demo/launch.py --configure
```

在隐藏输入处填写已有项目密钥（不回显属于正常）。若旧服务仍在运行，先在其终端 Ctrl+C 停止，再启动；也可通过网页 AI connection 临时填写地址 `https://api.deepseek.com`、模型 `deepseek-flash` 和密钥。不要把密钥写入检测报告或截图。

打开已确认记录的学生，选择下一轮、Live AI、所需材料语言并生成；查看请求是否包含本轮确认的评价、返回引用是否对应真实的任务 ID、生成失败是否明确说明。第二轮不必强制“难度增加”：本脚本仍有首次错误，合理结果可能继续巩固。保存实际变化与规划理由，不把“题目变了”本身当学习有效证据。该操作会调用付费 API。

## 8. 回传哪些文件，以及常见问题

建议建一个 `physical-test-日期` 文件夹，放入填写后的记录模板、同一轮三个 PDF、原始照片、识别前后截图、本轮 JSON 和完整备份。文件名带 package ID 与 P01/P02 等编号。若照片含真实姓名，回传前去除；技术测试优先只用匿名模拟档案。不要打包 `provider.json`。将该文件夹压缩发回，便于按具体字段定位问题。

| 现象 | 处理 |
|---|---|
| 启动脚本窗口关闭/打不开 | 在终端运行命令读错误，检查 Python 与工作目录；不需要安装 npm |
| 已配置但调用失败 | “configured”仅表示配置存在；保留错误码，检查网络/模型/密钥，不将规则结果冒充 AI |
| 打印按钮禁用 | 读页面错误；检查内容过长/页数预算。已发行不能原地改稿，另建一份合适的学习包 |
| 编号不匹配 | 对照纸面 package/Sheet；选回正确学习包，不手工更改编号绕过检查 |
| 定位失败 | 正向原图，四角完整；手动选四点，仍失败就重拍 |
| 选框模糊、多选 | 保留原图与原始识别结果，人工确认；无法确定就保持未知 |
| 合并备份冲突 | 不覆盖旧数据；保留错误说明，需要完整重建时在新的空测试数据库恢复 |

本指南依据 [0.2 本地验收报告](local_validation_02_results.md)与该版本程序入口编写。软件验收已通过的项目不必重装测试工具再跑一遍；本次重点是新的实物证据。
