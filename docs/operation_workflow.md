# 操作流程与纸张设计

> 本文为实现说明。示例学生与表现均为虚构演示数据，不是实验结果。配套：[系统架构](system_architecture.md)、[数据协议](data_contracts.md)。

## 1. 教师与学生入口

| 页面 | 主要内容 | 操作完成后的结果 |
|---|---|---|
| 教师：班级与学生 | 创建班级、分配匿名编号、导入名单；身份映射单独保存 | 学生档案 |
| 教师：教学任务 | 年级、语言、知识单元、目标、已学／排除内容、材料来源 | 本轮教学配置 |
| 教师：资源限制 | 离线天数、预计学习时长、学习册页数、记录纸页数、纸型、黑白／彩色 | 规划与编译约束 |
| 学生／教师代填：初始信息 | 学習经历、阅读与版面需求、困难自评 | 辅助信息，不直接当作能力结论 |
| 教师：扫描收件箱 | 拍照／上传、匹配编号、缺页与模糊提醒 | 待校对记录 |
| 教师：扫描校对 | 原图与字段并排，确认答案、提示使用与实际路径 | 确认记录 |
| 教师：方案审核与打印 | 学生状态、AI 调整理由、教学图、PDF 预览 | 已发行学习包 |
| 教师：轮次分析 | 首次正确率、提示依赖、补救表现、下一轮变化 | 更新证据与研究导出 |
| 学生：可选入口 | 查看自己的任务、下载学生版、查看回收后的反馈 | 无设备学生仍可只用纸张 |

演示版本使用英文界面。首版不要求学生逐一注册在线账号；多人或托管部署时，教师与学生的读取范围必须由服务端控制。

## 2. 第一轮：从建档到打印

1. **教师配置任务**：例如移项单元、3 天离线学习、黑白 A4、学习册最多 6 页、记录纸 1 页。页数和时间是可调整的设计值，不是竞赛规定。
2. **学生完成短诊断**：先打印统一诊断纸。初始没有历史记录时，不凭空生成掌握评分。
3. **教师本地扫描**：定位纸张、校正透视、识别模板版本、读取选框；可选短文字识别只能作为待确认结果。
4. **教师确认**：校对缺失、多选和低置信度字段，保留首次答案与修改后答案。确认操作生成记录版本与修正日志。
5. **程序评分与聚合**：根据冻结的题目版本评分，把观察到的表现与已有状态组合；无数据的知识点标为未知。
6. **请求 AI**：服务端提交目标、证据、原题、可用内容、资源约束和 JSON 输出协议。
7. **AI 规划**：提出误区假设、任务顺序、分支、提示和下一轮验证目标，并引用证据编号。
8. **程序与教师审核**：验证数据、内容、图路径和版面；教师批准内容，修改后重新检查。
9. **编译并打印**：生成学习册、独立记录纸、教师答案与路径版。登记包编号、版本、学生编号、发行时间。

## 3. 学生离线操作

学生先核对编号，按入口任务开始；每完成一题，先填“首次答案”，再按需要使用提示或跳转补救任务。提示使用和重试填写在单独位置；不要擦去首次答案。按照印出的任务编号与页码跳转，在终止节点完成退出小测和反馈。

选择题可以按选项直接跳转；短答案题首版不自动在纸上判分。需要当场判分时必须提供明确自查步骤，并要求先记录再查答案。不能假设 AI 在学生离线时实时观察。

记录纸采用顺序访问栏记录任务访问顺序，每行含 `visit_no` 与 `task_id`。任务专用答案区保存答案；未访问分支无需填写。这样可以发现跳错页、漏做和重复做，而非把一组无序答案误称为完整轨迹。

## 4. 三种纸质输出

| 输出 | 应包含 | 排版与记录要求 |
|---|---|---|
| 学生学习册 | 目标、操作说明、入口、题目、提示、补救讲解、跳转与结束检查 | 稳定任务编号；足够演算区；依赖颜色的信息应有文字／形状替代 |
| 独立记录纸 | 匿名编号、包编号与版本、模板编号、页码／总页数、访问顺序、答案、提示级别、重试与反馈 | 固定区域、四角定位标记、编号二维码、首次／重试分栏 |
| 教师版 | 正确答案、题目来源、误区解释、完整路径、AI 调整依据、审核信息 | 与学生版分开访问及打印 |

记录示意：

| 任务 | 首次答案 | 最高提示级别 | 重试答案 | 自评 |
|---|---|---|---|---|
| Q01 | A / B / C | 0 / 1 / 2 | A / B / C / 未重试 | 已理解 / 不确定 |
| Q02 | 短数字框 | 0 / 1 / 2 | 短数字框 / 未重试 | 已理解 / 不确定 |

二维码存不透明包编号、版本、模板编号、页号及校验信息；通过包元数据匹配匿名学生编号，不嵌入姓名、联系方式或完整答案。每页带可读编号作为扫码失败时的人工回退。

模板区域坐标由编译器输出，扫描端使用同一份模板数据；不能让生成与识别分别猜测版面。若任务超出一页容量，先减少任务；允许多页时明确总页数并检测缺页。

## 5. 第二次扫描与下一轮

扫描 → 识别包及版本 → 完整性检查 → 字段提取 → 人工确认 → 评分 → 状态更新 → AI 生成下一轮 → 审核 → 打印。

扫描结果和教育判断分开：识别置信度只反映“是否读清”，不代表“是否掌握”。空白细分为未访问、应完成未填写、无法识别、不适用；不能统一计错。模糊项目允许补扫或人工录入，始终记录来源。

每轮分析至少回答：哪些任务独立正确、哪些依赖提示、哪些错误重复出现、补救后能否迁移到新题。单个典型错误最多支持待验证的误区假设；下一轮安排新题确认。

## 6. 贯穿示例

| 时点 | 学生 S023 的演示行为 | 系统应做什么 |
|---|---|---|
| 初诊 | 将 `x + 2 = 6` 选为 `x = 8` | 记录答案；提出可能的符号误区，不能视作已证实 |
| 第一包 | Q01 答 B，进入 R01，阅读“等式两边同时减去同一数” | 纸上分支可以无设备执行 |
| 后续任务 | Q02：`x + 5 = 12`，独立填 7 | 记录补救后一次正确；尚不足以证明稳定掌握 |
| 回收 | 访问顺序 Q01、R01、Q02、END，首次答案与提示情况已填 | 扫描恢复事实，显示路径一致性 |
| 第二包 | 新题检验正负号与迁移；表现稳定后再进阶 | 显示本轮相较上一轮改变了哪些内容、基于什么证据 |

## 7. 状态与交接

学习包状态：`draft → validated → approved → issued → collecting → evaluated → archived`。扫描另有 `captured → needs_review → confirmed` 状态。下一轮是新包，不覆盖上一轮。

同一纸张重复上传只产生新的扫描尝试，不重复累计学习收益；确认更正产生记录新版本并重新评价。断网时保存本地草稿；教师确认同步成功后才能在另一设备继续。已经发给学生的材料不静默改版。

## 8. 示例 Demo 的最低操作顺序

展示一份教师配置、一份匿名学生状态、一次真实 AI 返回、一次校验与 PDF 生成；拿实印纸执行一个错误分支；扫描独立记录纸并演示一次校对；生成下一轮并说明调整理由。另备断网回放，但要标明它使用已保存结果。
