# 参赛材料内容框架

> 本文是内容设计，不是成品报告、海报或视频。章节英文标题可直接沿用；中文解释供内部实施。正式提交、作品展示、附件、字幕、简报和答辩使用英文。所有未测量结果写明待完成，正式交件时用真实结果或如实说明未测试，不能填造数据。
>
> 要求依据：[仓库章程](competition_rules.md)及[官方页面](https://www.mcs.mo/articles/104)，核对日期 2026-09-26。页数分配和章节结构是本项目建议，不是官方指定模板。若全球赛另有规则，另行核对。

## 1. 全部材料与统一信息

| 材料 | 格式与范围 | 本项目要准备的内容 |
|---|---|---|
| Project Introduction | 英文 PDF，建议不超过 2 页 | 问题、用户、功能、AI 方法、创新与影响 |
| Research Report | 英文 PDF，建议 6–12 页 | 背景至参考文献的完整证据链，详见下文 |
| Poster | 英文直向，0.8 m × 1.1 m，PDF | 能独立说明问题、机制、证据和边界 |
| Demonstration Materials | 作品照片及 ≤5 分钟英文视频 | 真正运作的纸上学习和回收闭环 |
| Final Presentation | 英文简报、可操作现场版本及备用演示 | 可解释、可操作、能回答实现与原创性问题 |
| 报名与支持信息 | 以报名系统当时字段为准 | 学校、队员与教师、类别、摘要、授权与同意核对 |

文字与海报 PDF 各不超过 50 MB；视频按报名系统支持的上传格式或可公开访问链接提交。文件建议命名为 `ProjectIntroduction_PAPERAI.pdf`、`ResearchReport_PAPERAI.pdf`、`Poster_PAPERAI.pdf`、`DemoVideo_PAPERAI.mp4`；如使用视频链接文件，以系统要求为准。

统一信息表应保存：英文项目名称、最终赛道、学校及队员官方英文名、指导教师、目标对象、研究范围、模型信息、原型版本、实际测试人数／日期、主要结果与局限。所有材料从同一份事实表取值。

## 2. Project Introduction：建议两页

| 页面与英文标题 | 具体写什么 | 需要准备的证据 |
|---|---|---|
| 第 1 页：Title and Project Snapshot | `PAPER AI: Compiling Adaptive AI Education into Paper`；一段说明短暂 AI 接入如何支持后续纸上个性化学习；列团队与最终类别 | 项目名称与登记信息 |
| Problem and Target Users | 网络／设备受限或希望低屏幕学习的教学场景；具体用户是教师与学生；区分实际试用对象与未来受益群体 | 教师需求记录或合适资料；没有实地调查就不冒称已完成 |
| Proposed Solution | 解释规划、纸上分支、独立记录纸、扫描与下一轮更新；用一次符号错误补救说明机制 | 一份真实可运行样例 |
| 第 2 页：AI Methods and Main Functions | 写明实际模型、输入证据、结构化输出、规则验证和教师审核；指出 AI 与扫描／排版的分工 | 请求响应、模型与提示词版本 |
| Innovation and Expected Impact | 说明把策略带到纸上、再从轨迹更新的组合；教育公平与 SDG 4 的联系。成本降低等尚未验证时写作目标 | 相关方案比较、成本记录或明确待验证假设 |
| Prototype, Evidence and Limitations | 说明完成到哪一步；给最有代表性的实测指标；说明样本与部署边界 | 运行截图、实印纸、测试汇总 |

项目介绍应让评委在两页内知道“为什么需要、怎样运行、AI 做了什么、凭什么相信”。技术细节放报告，不把所有功能挤成清单。

## 3. Research Report：建议十页内容框架

可调整为 6–12 页；下面给出十页的组织建议，含首页和参考资料位置。正文不依赖额外附件才能理解核心方法和结果。

| 页／章节 | 具体内容框架 | 配套图表与证据 |
|---|---|---|
| 1. Abstract and Project Overview | 问题、方法、原型范围、实际验证和局限；研究问题聚焦“多少教学逻辑可在纸上执行”；摘要在测试后最后更新 | 一幅闭环概念图；不预填成绩提升比例 |
| 2. Background, User Needs and Related Work | 目标环境、教师现有工作、设备和打印条件；比较静态纸张、分支教材、在线／离线 AI、OCR 方案；解释 SDG 关联 | 有来源的需求、相关工作对照表、引用 |
| 3. Problem Definition and Design Goals | 用户、输入输出、离线间隔、资源约束；可用性、轨迹恢复与学习效果问题；列假设、非目标和成功指标 | 研究问题—指标映射表 |
| 4. System Architecture and Workflow | 教师／学生端、本地／服务端／AI 分工；建档、扫描、确认、规划、编译、打印、回收、更新；故障与版本处理 | 架构图、两轮实例、模块表 |
| 5. AI Methods and Student Evidence | 实际模型／平台／版本、提示词、学生证据组织、误区假设、题库选择或生成、规则与教师核验；有无训练、数据来源 | 脱敏请求响应片段、提示词版本、诊断证据引用 |
| 6. Paper Compiler and Trace Recovery | 教学图、分支语义、提示、终止检查、布局与页码；独立记录模板、定位、识别、校对；哪些信息无法恢复 | 教学 JSON 片段、印刷样张、校对例子 |
| 7. Data and Evaluation Methods | 模拟／真实数据来源、样本与取得方式、同意流程、测试条件、前后测、三组设计或实际完成的较小范围；指标口径与缺失值 | 试验流程、评分标准、扫描测试条件 |
| 8. Results and Analysis | 填入真实运行成功率、恢复准确率、校对时间、前后测等；分开呈现技术结果与教育结果；解释失败案例 | 带样本量与单位的表／图、匿名个体变化、错误分析 |
| 9. Discussion, Limitations and Responsible AI | 对研究问题逐项回答；接入频率尚未证明的部分；成本、打印配送、环境、语言、可及性、隐私、偏差、版权和教师责任 | 局限—影响—缓解表；工具与学生贡献披露 |
| 10. Conclusion, Future Work and References | 只总结证据支持的结论；下一步是何种验证；完整列资料、模型、题库、代码与素材来源 | 参考文献、可复现版本信息；空间不足时调整前页 |

### 3.1 方法部分必须回答的问题

- AI 输入包含什么，如何知道学生的状态，哪些只是推测？
- AI 输出哪些教学决策，哪些检查由确定性程序或教师完成？
- 纸上如何选路径，遇到任意短答案和开放题时如何处理？
- 扫描恢复的是哪些字段，哪些必须人工确认，如何处理未知与误填？
- 同一学生第二轮为什么不同？指出实际证据与变化，不只展示两份随机题目。
- 模型调用失败、纸张缺页、页数超限时如何恢复？

### 3.2 结果表的具体字段

技术结果表：测试编号、程序版本、条件、样本数、自动正确字段、拒识字段、人工修正字段、确认后正确字段、处理时间、失败原因。

教育结果表：匿名参与者、组别、前测、后测、延迟测（如有）、实际学习时间、提示使用、教师帮助、缺失说明。汇总表列实际 n、平均／中位变化、范围或适当不确定性，保持分母明确。

成本表：每轮学习册页数、记录纸页数、API 用量与费用、扫描／审核／打印时间、网络数据量（如有测量）。未测能源不得从“屏幕更少”直接推出“更节能”。

### 3.3 AI 使用与学生贡献披露框架

| 工具／模型 | 版本或访问日期 | 用途 | 产生的内容 | 学生完成的工作 | 验证与修改方式 |
|---|---|---|---|---|---|
| 待填写 | 待填写 | 构思／资料辅助／代码／规划／识别等 | 如实记录 | 设计、实现、检查、实验、解释的真实范围 | 测试、审核、重写或排除 |

区分“系统运行使用的 AI”与“开发过程使用的 AI”。当前设计文档也属于 AI 辅助产物，应由学生审核并据实披露，不能把生成文档自动算作学生独立研究或已完成实现。队员需能够解释和操作自己的提交系统。

### 3.4 伦理、隐私、版权与授权内容

说明收集哪些数据、为何必要、存在哪里、哪些发送给 AI、谁能访问、保留多久及如何删除；真人测试与公开展示的适当同意由学校落实。题库、字体、代码、图像与模型均登记来源和许可。说明误诊、生成错误、语言偏差、自报提示偏差的影响及教师审核措施。提交前确认展示授权范围，未公开技术信息按官方要求明确标识。

## 4. Poster：只定义内容与体现重点

不在此设计版式、配色或视觉布局。

| 应包含的内容 | 应让观众理解或看到 |
|---|---|
| 项目名称、团队、目标用户与问题 | 一个具体教育需要，而不是泛泛的“AI 改变教育” |
| 核心闭环与真实纸质样例 | AI 如何离开、纸张如何继续工作、证据如何回来 |
| 一处分支与一处记录机制 | 纸张确实承担教学选择和学习记录 |
| AI 方法与程序验证 | AI 有实质作用，系统也有质量控制 |
| 已完成原型与测试结果 | 真实样本量、指标与测试范围；读者可独立判断证据 |
| 创新比较、教育／SDG 价值 | 与普通题目生成或批改的具体差异 |
| 局限、引用与必要披露 | 没有把计划当结果，没有把目标场景当已验证部署 |

## 5. Video：只定义内容与体现重点

不在此设计镜头、分镜、旁白全文或时间轴；成片控制在规定时长内，使用清晰英文说明。

| 应包含的内容 | 应体现的东西 |
|---|---|
| 使用情境与任务 | 为什么需要间歇式 AI，谁来打印和回收 |
| 基础设置与学生证据 | 个性化有输入依据 |
| 真实 AI 规划与方案验证 | 模型确实参与，合法 JSON 仍要检查 |
| 生成 PDF 与实印纸张 | 数据确实转成可用学习材料 |
| 学生沿错误分支学习并记录 | 脱离设备后仍能执行策略 |
| 本地扫描、校对与结构化结果 | 识别范围与人工参与真实可见 |
| 下一轮内容变化 | 从学习证据到教学调整的闭环 |
| 实际测试与限制 | 只展示有证据的效果；实时、录制、缓存演示标示清楚 |

## 6. 作品照片与现场材料

照片内容包括：学习册与独立记录纸、分支与提示实例、匿名填写样本、扫描校对界面、第一轮与第二轮差异、实际原型操作。使用可辨认文字的清晰照片，避免未获许可的人脸和身份信息。照片命名、具体数量和上传位置待核对报名系统，不自行宣称官方规定。

英文现场简报建议按“问题—设计—AI 方法—纸上执行—扫描—结果—局限—下一步”组织；不是固定页数要求。准备可操作版本、打印样包、已保存输入输出、离线视频和截图。网络失效时展示缓存并说明，不能说是现场生成。

所有参赛队员按实际分工参与演示和问答，具体时长、设备与场地限制待通知。答辩问题库应覆盖：为什么必须 AI、与分支教材差别、误区诊断依据、扫描准确率分母、测试公平性、隐私与成本、个人贡献、为何不能凭短试验声称最低接入频率。

## 7. 评审维度对应的证据

| 维度 | 项目应提供的证据 |
|---|---|
| 问题与教育价值（20%） | 明确用户、真实需求或有来源的场景、SDG 关系、可执行使用条件 |
| 创意与原创性（20%） | 相关工作比较、策略编译与轨迹更新机制、原创与复用边界 |
| AI 技术运用（25%） | 真实调用、模型／提示词说明、输入输出、验证机制、学生解释 |
| 原型与测试（20%） | 两轮闭环、实印扫描、失败案例、真实数据与改进 |
| 英文展示（10%） | 全套英文材料、清晰术语、可操作演示与共同答辩 |
| 伦理与隐私（5%） | 匿名化、同意、访问与删除方案、来源许可、AI 与学生贡献披露 |
