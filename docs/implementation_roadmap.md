# 实施路线与任务清单

> 更新：2026-09-27，0.2 主要软件验收已完成；最新依据为 `23bd7bd` 和 [0.2 验收报告](local_validation_02_results.md)。以下日期保留为原建议计划，不代表阶段仍未启动；当前首要任务是实印实拍。章程时间以仓库保存版本为依据，本次未重新核验官方变更。

## 1. 按依赖推进

| 阶段 | 建议时间 | 工作 | 具体产物与验收 |
|---|---|---|---|
| 范围冻结 | 9/26–9/27 | 确认赛道、学科、目标学生、题库、记录字段、英文术语、分工 | 一份冻结需求；纸上手工跑通一条正常与补救路径 |
| 确定性主干 | 9/27–9/29 | 表单、数据对象、固定教学图、编译器与三类 PDF | 示例 JSON 能生成可实际打印的材料；明确仍是固定样例 |
| 真实 AI 接入 | 9/29–10/1 | 请求、结构化响应、校验、教师审核、发行版本 | 不同学生证据得到可解释的不同方案；错误输出被拒绝 |
| 扫描闭环 | 10/1–10/3 | 定位识别、人工校对、评分、状态更新、第二轮 | 实印填写再扫描；修改有日志，重复提交不重复计分 |
| 验证与研究 | 10/3–10/5 | 工程测试；条件满足时开展小规模试用 | 完整测试记录、真实 n、失败案例、局限；真人研究先落实同意 |
| 材料制作 | 10/5–10/7 | 英文介绍、报告、海报内容、照片、视频、简报 | 结果与证据对应，不虚构未完成研究 |
| 复核与交件 | 10/8–10/9 | 文件、语言、大小、链接、授权、备用演示、报名 | 最终版本和回执；尽量在截止前留出修正时间 |

长周期保持效果和接入频率比较若无法在交件前完成，明确列为后续研究，不压缩成无效实验后宣称得出结论。

## 3. 首版完成后再考虑

卡片和折叠活动、多知识单元、复杂手写推导、多模型比较、更复杂知识追踪、长期随机对照与多间隔试验。只有核心闭环可靠后再扩展，避免功能数量掩盖纸上执行和扫描恢复问题。

## 4. 待团队确定的决策

| 决策 | 建议起点 | 决策依据 |
|---|---|---|
| 参赛赛道 | 欠发达地区／教育二选一 | 实际需求证据与能测试的范围 |
| 首个单元 | 一元一次方程移项 | 误区可设计、答案可验证、分支清楚 |
| AI 模型与平台 | DeepSeek 已接入，保留兼容接口 | 结构化输出可靠性、质量、费用、可访问性 |
| 部署方式 | 本地单教师应用 | 手机照片传到电脑；不支持手机直接访问电脑的 localhost |
| 扫描技术 | 定位标记＋选框优先 | 是否能低成本稳定恢复所需证据 |
| 真实试用 | 待学校与参与者条件确认 | 同意、人数、时间、测量可行性 |
| 页数与打印配置 | A4 黑白、学习册最多 6 页＋记录纸 1 页作为起点 | 实印可读性和任务容量 |

## 5. 分工与贡献记录

建议工作包为教学与研究、程序与数据、验证与英文展示；人数不固定假设为三人，可按实际队伍合并。每名学生记录实际做过的设计、实现、检查、实验和材料修改，指导教师记录审核与组织支持。AI 辅助内容单独登记，队员需要理解并能复现本人负责部分。

每次迭代记录：日期、负责人、目标、变更、证据、未解决问题、AI 或第三方帮助。任务完成必须附实际产物，不能仅凭“已讨论”勾选“已实现”。

## 6. 首版交付门槛

能够向不熟悉项目的人演示“配置—AI 方案—打印—纸上错误分支—记录—扫描校对—下一轮变化”；观察者能理解纸上如何执行。展示实际测试证据，解释 AI 与程序分工、主要限制和各成员贡献。相关文档入口见 [README](../README.md)。
